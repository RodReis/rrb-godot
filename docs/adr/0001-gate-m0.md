# ADR-0001 — Gate do M0: Godot 4 + netfox para ação em rede

**Status:** proposto — em teste
**Data do teste:** 2026-10-09
**Decisor:** Rodrigo Reis (PI)
**Relacionados:** PRD §9.1 e §10.3 (risco R1), `docs/prd/mvp/MVP-0.md`, issue #7, roteiros `game/test/net/roteiro-f3..f5-*.md`

## Contexto

O PRD exige provar, antes de qualquer conteúdo, que Godot 4.7 + netfox entrega movimento com predição e um ataque validado no servidor **jogáveis a 100 ms de RTT**. Se não entregar, o projeto migra para Unity (Fish-Net ou Photon Fusion) antes do M1.

O spike (F1–F5, PRs #8–#14) entregou:
- servidor headless autoritativo em Docker com `tc netem`;
- 2 clientes com movimento por rollback (`RollbackSynchronizer`, input só por `BaseNetInput`, input do cliente validado no servidor);
- ataque corpo a corpo resolvido só no servidor, com o dano aplicado pelo `HitLedger` no `_rollback_tick` do alvo;
- HUD de RTT/tick e autopilot para teste solo.

Desvios do plano e riscos conhecidos estão nos comentários de encerramento dos cards #2–#6.

## Protocolo

O Code sobe o servidor em Docker e os 2 clientes (o 2º em autopilot). O PI controla o cliente 1. Cada cenário dura 10 minutos.

| Cenário | Ambiente |
|---|---|
| A — base | sem `NETEM_*` |
| B — alvo do gate | `NETEM_DELAY_MS=100`, `NETEM_LOSS_PCT=2` |
| C — estresse | `NETEM_DELAY_MS=200`, `NETEM_JITTER_MS=30`, `NETEM_LOSS_PCT=5` |

**Regra de decisão:**
- **Segue Godot** se B tiver todos os itens OK.
- **Migra para Unity** (Fish-Net ou Photon Fusion) antes do M1 se, no cenário B, os itens 1, 2, 3 ou 6 falharem e não se resolverem em até 2 dias de ajuste (tickrate, interpolação, configuração do netfox).
- C é informativo e não bloqueia.
